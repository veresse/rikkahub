## 一、v1 到 v2 架构切换全景与需求差异对齐

### 1.1 组件处置总表（保留 / 升级 / 新增 / 移除）

| 模块 / 路径 | v1 现状 | v2 目标动作 | 核心变化说明 |
| :--- | :--- | :--- | :--- |
| 根目录 RikkaHub Android 工程（`app/` 等） | 原始项目，禁止破坏 | **严格只读保留** | 不修改原项目代码与根 `settings.gradle.kts`，继续保留原 App 回归检查 |
| `companion/web` | React + Vite 管理网页 | **移除（新分支清理）** | v2 明确取消网页管理端；在从 `feature/companion-server` 切出的新分支中删除，保留 v1 分支作为历史参考 |
| `companion/app` | 无 | **全新新增（独立 Gradle 工程）** | Android 原生 App（Kotlin + Jetpack Compose + Retrofit + OkHttp WSS，`minSdk = 26`），含登录、角色、聊天、导入、设备、遥控面板、设置 |

| `companion/docs` & 部署脚本 | v1 架构/Nginx（含静态网页）/烧录指南 | **同步改订** | Nginx 移除静态网页并新增 `/app/ws` 反代；补齐散件接线、5V 独立供电、装机前归零、App 校准与 APK 打包手册 |

### 1.2 两版文档中的关键边界与口径统一（必须遵守）

在对比第一版与第二版方案后，以下 4 处细节在实现前统一口径，避免各端写出前后矛盾的代码：

1. **俯仰轴（`tilt`）角度范围统一**：第二版方案 10.1 节工具表写为 `tilt (0...45)`，14.1 节动作库定义为 `tilt` 中位 $0^\circ$、安全范围 $-20^\circ$（抬头）至 $+45^\circ$（低头）。由于 `look_up`、`surprised`、`wake`、`tilt_left/right` 均需要抬头负角度，**全链路统一采用 `tilt` $\in [-20, +45]$（单位：度，中位为 $0^\circ$），`pan` $\in [-90, +90]$**，具体行程以实机校准后配置为准。
2. **动作时长上限与 `dance` 特例**：第二版方案规定普通单动作强制超时上限为 $3000\text{ms}$，但 `dance` 预设组合序列时长为 $2000\text{–}5000\text{ms}$。实现上采用：**默认全局上限 $3000\text{ms}$，固件硬顶 $5000\text{ms}$，仅允许动作表中显式声明 `max_duration_ms` 的白名单动作（如 `dance`）放宽至 $\le 5000\text{ms}$**。
3. **Android App 工程隔离**：根仓库是带 `google-services.json` 依赖的多模块 Android 项目，**严禁将 `companion/app` 加入根目录 `settings.gradle.kts`**。`companion/app` 必须是完全独立的 Gradle 工程，自带 `settings.gradle.kts`、`build.gradle.kts` 与 Gradle Wrapper，互不污染。
4. **明确不做的范围（Out of Scope）**：严禁自行添加或过度设计以下功能——小米运动健康读取、定时或随机主动问候、4G 模组、摄像头视觉、世界书、正则规则、逐字/音素级口型同步、第三颗 Roll 轴真歪头舵机、AEC 全双工回声消除、远程不安全 OTA、应用商店分发。

## 二、给 Code Agent 的全局执行铁律

1. **分支隔离**：从当前 `feature/companion-server` 切出新分支 `feature/companion-robot-v2` 进行所有改动，绝不覆盖或破坏 v1 提交历史及主分支代码。
2. **数据与隐私红线**：
   - 绝不向用户索要、打印或记录真实 API Key（DeepSeek / 阿里云百炼）、RikkaHub 真实备份 ZIP 内容、Wi-Fi 密码、管理员密码或完整私密聊天正文。
   - 默认不落盘、不入库、不打印原始音频，仅做短暂内存缓冲。
   - 绝不自动改写用户导入的角色设定（`system prompt` 等）。
   - 严禁在 Android App 或 ESP32 固件中提供“跳过 TLS 证书校验”选项。
3. **诚实汇报与实测边界**：
   - 每个 Phase 结束必须输出：
     1. 已完成项与改动文件清单；
     2. 实际执行的命令与真实输出（通过/失败/跳过及原因）；
     3. 未实现项或阻塞点；
     4. 下一步计划。
   - 缺真机或真实云账号时，**必须明确标注“仅通过 Mock/模拟器验证，真实硬件/云端联调未完成”**，严禁用模拟器测试冒充真机验收。
4. **分批交付门禁**：严格按 Phase 0 到 Phase 7 顺序推进，**每个 Phase 自动化测试全部通过并经用户确认后，再进入下一 Phase**。

### Phase 1：共享动作库规范与 `companion.v2` 协议定稿

**目标**：建立 Server、App、Firmware 三端共享的协议契约与动作目录，先定规范再写代码。

#### 1.1 单一事实源：`companion/shared/actions.json`

创建 `companion/shared/actions.json`（及校验脚本/JSON Schema），完整对齐第二版方案 14.1 节的 16 类语义动作（共 18 个动作名），参数设计如下：

- **全局机械与档位约定**：
  - `pan`（水平轴）：中位 $0^\circ$，安全硬限位 $[-90, +90]$（负=左，正=右，组装校准时统一方向）。
  - `tilt`（俯仰轴）：中位 $0^\circ$，安全硬限位 $[-20, +45]$（负=抬头，正=低头）。
  - `intensity`（强度档位 `1 | 2 | 3`）：幅度缩放系数约 `0.33 / 0.67 / 1.0`。
  - `speed`（速度档位 `1 | 2 | 3`）：单程运动耗时约 `900ms / 500ms / 300ms`。
  - `repeat`（重复次数）：默认 `1`，合法范围 `1..5`。
- **18 个标准动作清单**：

| 动作名 (`name`) | 语义 | 使用轴 | 默认参数与行为关键帧说明 | 联动表情 (`linked_expression`) | 最大时长上限 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `home` | 归位 | `pan+tilt` | 平滑回至校准中位 `(0, 0)` | 无（保持状态） | `3000ms` |
| `nod` | 点头/同意 | `tilt` | `intensity 1-3`（轻/中/用力低抬头）、`speed 1-3`、`repeat 1-5` | 无 | `3000ms` |
| `shake` | 摇头/否定 | `pan` | `intensity 1-3`（缓/中/快左右摇）、`speed 1-3`、`repeat 1-5` | 无 | `3000ms` |
| `look_left` | 看向左边 | `pan` | 默认 `pan = -45`（随 `intensity` 缩放到 `-25 / -45 / -75`） | 无 | `3000ms` |
| `look_right` | 看向右边 | `pan` | 默认 `pan = +45`（随 `intensity` 缩放到 `+25 / +45 / +75`） | 无 | `3000ms` |
| `look_up` | 抬头 | `tilt` | 负向抬头（随 `intensity` 缩放到 `-8 / -14 / -20`） | 无 | `3000ms` |
| `look_down` | 低头 | `tilt` | 正向低头（随 `intensity` 缩放到 `+15 / +30 / +45`） | 无 | `3000ms` |
| `look_around` | 环视 | `pan+tilt` | 左右各看一次并回中，支持 `speed` | 无 | `3000ms` |
| `bow` | 鞠躬/感谢 | `tilt` | 低头保持短暂停顿后回中，深度随 `intensity` | 无 | `3000ms` |
| `peek` | 探头偷看 | `pan+tilt` | 小幅 `pan` 偏移 + 微低/抬头停顿后回位 | 无 | `3000ms` |
| `surprised` | 惊吓 | `tilt` | 快速抬头至 `-18` + 短停顿 + 回位 | `surprised` | `3000ms` |
| `sleep` | 睡觉 | `tilt` | 缓慢低头至 `+35` 保持（不自动回中直到唤醒/新指令） | `sleep` | `3000ms` |
| `wake` | 唤醒 | `tilt` | 从低头缓慢抬至 `0` + 一次小幅 `nod` | `idle` | `3000ms` |
| `panic` | 慌张 | `pan` | 快速小幅连续左右急摇（$\pm 15^\circ \text{–} \pm 25^\circ$） | `surprised` | `3000ms` |
| `swing` | 兴奋摇摆 | `pan` | 中幅连续左右韵律摆动（拟态身体摇摆） | 无 | `3000ms` |
| `tilt_left` | 向左歪头（拟态） | `pan+tilt` | `pan` 小角度左偏 + `tilt` 微抬组合 | 无 | `3000ms` |
| `tilt_right` | 向右歪头（拟态） | `pan+tilt` | `pan` 小角度右偏 + `tilt` 微抬组合 | 无 | `3000ms` |
| `dance` | 舞蹈 | `pan+tilt` | 预设多关键帧组合序列 | 无 | `5000ms` |

#### 1.2 协议规范文档：`companion/docs/protocol_v2.md`

在保留 `companion.v1` 全部音频帧、状态机与流控规范的基础上，明确 `companion.v2` 扩展规格（JSON 控制消息统一包含 `v: 2`、`type`、`session_id`，必要时含 `turn_id`）：

1. **握手能力协商（`hello` / `hello_ack`）**：
   - 设备上行 `hello` 新增：`v: 2`、`capabilities: ["action", "volume", "expression"]`、`audio: { uplink: ..., downlink: ... }`、`firmware_version`、`action_catalog_version`。
   - 服务端若收到 `v: 1` 设备，则按音频纯通道降级处理（不注入动作工具、不下发 v2 控制消息）。
2. **新增下行消息（Server -> Device）**：
   - `action.play`: `{"v": 2, "type": "action.play", "action_id": "uuid", "name": "nod", "intensity": 2, "speed": 2, "repeat": 2, "source": "llm" | "app"}`
   - `servo.move`: `{"v": 2, "type": "servo.move", "action_id": "uuid", "pan": -30.0, "tilt": 10.0, "speed": 500, "source": "llm" | "app"}`
   - `volume.set`: `{"v": 2, "type": "volume.set", "action_id": "uuid", "volume": 60, "source": "llm" | "app"}`
   - `expression.set`: `{"v": 2, "type": "expression.set", "name": "surprised"}`
   - `idle.set`: `{"v": 2, "type": "idle.set", "enabled": true}`
   - `action.stop`: `{"v": 2, "type": "action.stop", "reason": "user_stop" | "barge_in"}`
   - 校准专用消息（供 App 校准模式使用）：`servo.calibrate_preview`（`pan_offset`、`tilt_offset` 实时微调预览）与 `servo.calibrate_save`（持久化写入 NVS 并回复 `action.result` + `device.report`）。
3. **新增上行消息（Device -> Server）**：
   - `action.result`: `{"v": 2, "type": "action.result", "action_id": "uuid", "status": "done" | "failed" | "timeout", "detail": "..."}`
   - `device.report`: `{"v": 2, "type": "device.report", "volume": 60, "pan": 0.0, "tilt": 0.0, "idle": true, "power": "usb", "state": "idle" | "listening" | "thinking" | "speaking" | "error", "pan_offset": 0.0, "tilt_offset": 0.0}`
4. **App WebSocket 通道规范（`wss://<host>/app/ws`）**：
   - 鉴权：Header `Authorization: Bearer <app_token>`（严禁将明文 Token 放在 URL Query 中，防止 Nginx 访问日志泄露；Android OkHttp 原生支持自定义 WS Header）。
   - App 上行控制消息：`remote.volume.set`、`remote.action.play`、`remote.servo.move`、`remote.idle.set`、`remote.action.stop`、`remote.calibrate.preview`、`remote.calibrate.save`（均显式携带 `device_id` 与客户端生成的 `request_id`）。
   - Server 下行广播事件：`device.status`（在线/离线）、`device.report`、`action.result`、`conversation.turn_state`（同步当前会话是否正在生成回复）。
5. **双源指令仲裁规则（LLM `ActionOrchestrator` vs App `AppGateway`）**：
   - 每个在线设备在服务端维护唯一调度队列：
     - `action.stop`：**最高优先级**，立即清空待执行动作队列并下发急停；
     - `volume.set` / `servo.move`：**覆盖语义（Last-Write-Wins）**，后到覆盖同类型未发出指令，并做速率限制；
     - `action.play`：**FIFO 排队语义**，按序下发执行；
     - 设备离线时：**直接返回 `failed (device_offline)`**，严禁缓存待设备上线后补发。

**Phase 1 验收标准**：
- `companion/shared/actions.json` 与 `companion/docs/protocol_v2.md` 落盘并通过 JSON Schema 校验测试。

### Phase 2：服务端升级（`companion/server`）、数据库迁移与移除 `companion/web`

**目标**：在不破坏 v1 已有核心功能（导入、角色、聊天、记忆、搜索、ASR/TTS、v1 音频状态机）的前提下，完成服务端全部 v2 能力建设并彻底清理 `companion/web`。

#### 2.1 数据库 Schema 与可逆 Alembic 迁移
新增独立 Alembic 迁移脚本（必须实现 `upgrade()` 与 `downgrade()` 并在测试库验证双向迁移）：
- `roles`（或现有角色表）新增列：`enable_action_sync`（BOOLEAN，默认 `True`，允许按角色开关动作联动）。
- `devices`（或现有设备表）新增列：`protocol_version`（INT，默认 `1`）、`capabilities_json`（TEXT/JSON）、`volume`（INT，默认 `70`，约束 `0..100`）、`idle_enabled`（BOOLEAN，默认 `True`）、`pan_offset`（FLOAT，默认 `0.0`）、`tilt_offset`（FLOAT，默认 `0.0`）、`last_report_json`（TEXT/JSON）、`last_seen_at`（DATETIME）。
- 新增 `app_tokens` 表：`id`、`admin_user_id`、`token_hash`（仅存 SHA-256/HMAC 哈希，绝不存明文）、`device_name`、`created_at`、`last_used_at`、`expires_at`、`revoked_at`。
- 保持 SQLite 单写进程、WAL、`foreign_keys=ON`、`busy_timeout` 与事务一致性规范不变。

#### 2.2 鉴权层重构（适配 Android 原生 App）
- 新增/完善 App 认证路由：
  - `POST /api/auth/login`：校验管理员账号密码，保留登录失败限流（防爆破），签发高熵 App Bearer Token 并写入 `app_tokens`。
  - `POST /api/auth/logout`：撤销当前 Token。
  - `GET /api/auth/tokens` 与 `POST /api/auth/tokens/{token_id}/revoke`：查看与独立撤销任意已登录手机的 Token。
- 所有业务 REST 接口统一支持 `Authorization: Bearer <app_token>`，**且与 `device_token` 严格权限隔离**（设备 Token 绝对不能访问管理/角色/聊天/导入接口，App Token 也不能冒充设备接入 `/device/ws`）。
- 确认配对接口（生成短期一次性配对码、限时/限次/限速、HTTPS 换取高熵 `device_token`）可通过 App Bearer Token 完整调用。

#### 2.3 新增 `ActionOrchestrator` 服务
实现独立模块 `ActionOrchestrator`（依赖注入 `DeviceGateway` 与 `ActionCatalog`）：
- **动态工具注入**：在 `ChatOrchestrator` 组装 DeepSeek 请求前查询绑定设备状态：
  - 仅当「角色开启 `enable_action_sync`」且「目标设备在线」且「设备支持 `companion.v2` 及相应 capability」时，向 DeepSeek 注入以下 5 个工具（工具 `description` 从 `companion/shared/actions.json` 动态生成，写清动作名、强度 `1/2/3` 与速度 `1/2/3` 语义）：
    1. `robot.action(name, intensity=2, speed=2, repeat=1)`
    2. `robot.move_head(pan, tilt, speed=500)`（范围校验：`pan` $\in [-90, 90]$，`tilt` $\in [-20, 45]$，`speed` $\in [0, 1000]$）
    3. `robot.set_volume(volume)`（范围校验：`volume` $\in [0, 100]$）

- **防滥用与安全限流**：
  - 单轮对话动作类工具调用次数上限默认 **3 次**（可配置，超出则返回结构化超限错误给模型，不实际下发设备）。

  - 与搜索工具共存：保留 v1 全部搜索防注入、公网 URL 白名单（禁止内网/本机/云元数据 SSRF）、流式 tool-call 聚合逻辑。
- **边说边动（并行编排）**：
  - `robot.action` / `robot.move_head` / `robot.set_volume` 下发后，支持通过 `action_id` 异步等待回执（带超时，如 `max_duration_ms + 1500ms`），并确保动作执行**不阻塞 TTS 分句流式播报**；模型收到工具执行结果（`done`/`failed`/`timeout`）后可自然续说（如点头后回复“嗯嗯，收到”）。

### Phase 5：ESP32-S3 桌面机器人固件重构（`companion/firmware`）

**目标**：将固件从 v1（ESP-VoCat 挂件）重构为 v2 散件 DIY 桌面机器人（ESP32-S3-DevKitC-1 N16R8 + GC9A01 + INMP441 + MAX98357A + 双 SG92R/SG90 + 按键），实现完整 `companion.v2` 协议、动作引擎、安全保护与自检校准工具。

#### 5.1 硬件抽象与统一引脚配置
- 锁定 ESP-IDF 版本（例如 ESP-IDF v5.3/v5.4 LTS，在 `companion/firmware/README.md` 与 `idf_component.yml` 中明确版本），不虚构未验证的第三方小智板级 BSP。
- 创建唯一引脚配置头文件 `main/board_pins.h`（全部通过 `Kconfig.projbuild` / `menuconfig` 可覆盖），默认严格对齐第二版方案 13.2 节建议分配：
  - **INMP441（I2S RX）**：`BCLK = GPIO 4`, `WS = GPIO 5`, `SD = GPIO 6`（硬件 L/R 接 GND，VDD 接 3V3）
  - **MAX98357A（I2S TX）**：`DIN = GPIO 7`, `BCLK = GPIO 15`, `LRC = GPIO 16`（硬件 GAIN 悬空，VIN 接 5V）
  - **GC9A01 1.28" `240x240`（SPI）**：`CLK = GPIO 10`, `MOSI = GPIO 11`, `RES = GPIO 14`, `DC = GPIO 8`, `CS = GPIO 9`, `BL = GPIO 2`
  - **双 9g 舵机（LEDC PWM）**：`PAN = GPIO 17`, `TILT = GPIO 18`（外部 5V $\ge 2\text{A}$ 独立供电 + 共地）
  - **对话按键**：`BUTTON = GPIO 21`（内部上拉，按下接地，20ms 消抖，短按释放判定，长按阈值默认 1500ms 可配）

#### 5.2 LEDC 双舵机驱动与安全保护引擎（`servo_driver`）
- **PWM 规格**：使用 ESP-IDF `driver/ledc.h`，固定频率 **50 Hz**（20ms 周期），脉宽 $500\text{–}2500\ \mu\text{s}$ 线性映射至 $0^\circ\text{–}180^\circ$（机械中位 $90^\circ = 1500\ \mu\text{s}$），避免 SG90/SG92R 高频滋滋异响。
- **坐标系与校准偏移**：
  - 从 NVS 读取 `pan_offset`、`tilt_offset`（默认 `0.0`）。
  - 逻辑角度转物理角度：
    $$\text{phys\_pan} = 90.0 + \text{clamp}(\text{pan}, -90, 90) + \text{pan\_offset}$$
    $$\text{phys\_tilt} = 90.0 + \text{clamp}(\text{tilt}, -20, 45) + \text{tilt\_offset}$$
    最终再次硬限位在 $[0, 180]$ 内，确保任何异常都不会输出越界脉宽。
  - **越界处理**：收到超出 `pan` $\in [-90, 90]$ 或 `tilt` $\in [-20, 45]$ 的指令时，截断至安全边界（或拒绝移动）并立即上报 `action.result(status="failed", detail="angle_out_of_range")`。
- **平滑插值与防抖**：独立 FreeRTOS 运动任务以 **20ms 固定步进**做平滑插值（ease-in-out），消除阶跃抖动与结构冲击。
- **停 PWM 防过热机制**：每次动作或移动到达目标角度并稳定 300ms 后，自动调用 `ledc_stop()` 释放舵机 PWM 信号，消除堵转电流与发热；下次动作前重新使能。
- **多重安全护栏**：
  - 单动作硬件看门狗定时器：默认 $3000\text{ms}$（`dance` 最多 $5000\text{ms}$），超时强制中止动作、回中停 PWM 并上报 `timeout`。
  - 固件侧速率限制：入站动作指令超过 **10 次/秒**时丢弃多余指令并上报 `failed (rate_limited)`。
  - `action.stop` 最高优先级信号量：10ms 内打断当前插值循环，立即平滑回中并停 PWM。

#### 5.3 动作解释器与待机微动作（`action_engine`）
- 将 `companion/shared/actions.json` 编译为固件内置只读配置表（通过构建期 Python 脚本校验一致性或直接嵌入 SPIFFS/LittleFS 分区，确保改档位不改协议）。
- 完整实现 18 个预设动作的关键帧解析与 `intensity` / `speed` / `repeat` 参数缩放。
- **待机随机小动作**：仅在设备状态机为 `IDLE` 且 `idle_enabled == true` 时启用；每 $4000\text{–}9000\text{ms}$ 随机选取 $\pm 30^\circ$ 内小幅张望目标，单次时长 $\le 600\text{ms}$；一旦按键进入 `LISTENING`、`THINKING`、`SPEAKING` 或 `ERROR` 立即暂停并归位。
- **表情联动**：执行 `surprised`、`sleep`、`wake`、`panic` 等带 `linked_expression` 的动作时同步通知 UI 渲染线程切换对应表情状态。

#### 5.4 音频、音量解耦与显示系统
- **音量与收音彻底分离**：
  - I2S 播放链路在解码 Opus -> PCM 后、写入 MAX98357A 前，按 `volume (0–100)` 做感知曲线（二次/对数衰减）软件乘法；当 `volume == 0` 时写入全零静音帧，**绝不关闭音频播放状态机**（`SPEAKING`、`segment_played`、按键打断 `cancel` 全部照常流转）。
  - INMP441 麦克风采集增益完全固定在独立配置中，不受 `volume.set` 影响；半双工机制保留（`SPEAKING` 期间暂停麦克风采集与上传）。
- **GC9A01 `240x240` 显示与动画**：
  - 替换/适配显示驱动为 `esp_lcd` + GC9A01（`240x240` 圆形安全区），默认内置轻量占位图包（`idle` 眨眼、`listening` 麦克风图标、`thinking` 思考/搜索图标、`speaking` 按播放音量 RMS 开合嘴、`surprised`、`sleep`、`error` 断网提示）。
  - 播放音量 RMS 计算与渲染线程彻底解耦，禁止刷屏阻塞录音或 Opus 解码；支持认证后的素材包热替换与损坏自动回退占位图。
  - 静音状态下屏幕可选显示回复文字摘要或表情动画，状态指示与麦克风真实开关严格一致。

#### 5.5 协议 v2、配网、硬件自检与归零工具
- 升级 WebSocket 客户端至 `companion.v2`：接入新控制消息、发送 `action.result` 与 `device.report`；保持 Wi-Fi 断线重连、NTP 时间同步、可信根证书 TLS 校验（绝不关闭校验）、配对换 Token、NVS 存储凭据、长按/串口恢复出厂清除凭据。
- **USB 串口本地配网与调试命令**：保留并扩展本地串口 CLI（不经公网、不写死源码）：
  - `provision`：写入 Wi-Fi SSID/密码与服务器 HTTPS 地址；
  - `selftest <screen|mic|speaker|button|servo_pan|servo_tilt|all>`：分项硬件自检模式，对应第二版方案 13.1 节第 1 步裸板验证；
  - `zero`（装机前归零模式）：将水平与俯仰舵机精准驱动至机械中位 $90^\circ$（忽略偏移量）并在串口提示“已归零，请立即断电并安装云台舵盘”；

- **宿主端（Host-side）单元测试**：使用 CMock / Unity 或纯 C 测试目标在 Linux/macOS 开发机直接测试角度限位、偏移叠加、20ms 插值轨迹、动作超限/超时逻辑、音量 0–100 衰减曲线与状态机转换（无真机也可自动化回归）。
